# Standard Phase Completion Report

This document must be followed after the implementation of EVERY phase.

Do NOT start the next phase until this report has been generated.

---

# Objective

Produce a complete implementation report for the completed phase.

The report should be written as professional project documentation.

Save the report as:

reports/Phase-XX-Report.md

Replace XX with the completed phase number.

Example:

reports/Phase-03-Report.md

---

# Report Structure

## 1. Phase Information

- Phase Number
- Phase Name
- Completion Date
- Status

---

## 2. Objective

Describe the objective of this phase.

---

## 3. Executive Summary

Explain what was accomplished.

---

## 4. Scope Covered

Explain every completed task.

---

## 5. Features Implemented

For every feature include:

- Name
- Purpose
- Files involved
- Important implementation notes

---

## 6. Architecture Changes

Describe:

- folders
- modules
- utilities
- services
- components
- configuration

---

## 7. File Changes

### New Files

List every new file.

### Modified Files

List every modified file.

Include a short explanation.

---

## 8. Dependencies

List:

- new packages
- versions
- purpose

---

## 9. Configuration Changes

Describe configuration updates.

---

## 10. Database Changes

If applicable:

- models
- enums
- relationships
- indexes
- migrations
- seed

Otherwise explicitly state:

"No database changes."

---

## 11. API Changes

If applicable.

Otherwise:

"No API changes."

---

## 12. UI Changes

If applicable.

Otherwise:

"No UI changes."

---

## 13. Testing

Include results for:

- build
- lint
- tests
- migrations
- validation

---

## 14. Security

Explain security improvements.

If none:

"No security changes."

---

## 15. Performance

Explain optimisations.

If none:

"No performance changes."

---

## 16. Known Issues

List:

- limitations
- technical debt
- assumptions

---

## 17. Remaining Work

Explain what remains for future phases.

---

## 18. Risks

Mention risks.

---

## 19. Git Summary

Include:

- branch
- commit
- files changed

---

## 20. Metrics

Include:

- files added
- files modified
- lines added
- lines removed
- components
- APIs
- models

Approximate values are acceptable.

---

## 21. Lessons Learned

Describe important design decisions.

---

## 22. Handover Notes

Provide everything the next phase should know.

---

# Final Checklist

Confirm:

✓ Build passes

✓ Lint passes

✓ Tests pass

✓ Documentation updated

✓ Report saved

✓ Ready for approval

---

Stop after saving the report.

Do NOT begin another phase.
