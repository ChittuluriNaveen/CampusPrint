# CampusPrint -- Accessibility Guide

## 1. Purpose

This guide defines accessibility requirements so CampusPrint can be used
by people with diverse abilities and complies with recognised
accessibility standards.

------------------------------------------------------------------------

# 2. Objectives

-   Build inclusive user experiences
-   Improve usability for all users
-   Support keyboard-only navigation
-   Ensure screen reader compatibility
-   Meet WCAG 2.1 Level AA where practical

------------------------------------------------------------------------

# 3. Accessibility Principles

-   Perceivable
-   Operable
-   Understandable
-   Robust

------------------------------------------------------------------------

# 4. Colour & Contrast

-   Maintain sufficient colour contrast
-   Do not rely on colour alone to convey information
-   Provide visible focus indicators

------------------------------------------------------------------------

# 5. Keyboard Accessibility

-   All interactive elements must be keyboard accessible
-   Logical tab order
-   Skip-to-content link
-   No keyboard traps

------------------------------------------------------------------------

# 6. Screen Reader Support

-   Semantic HTML
-   Descriptive labels
-   ARIA attributes only when necessary
-   Meaningful page titles and headings
-   Alternative text for images

------------------------------------------------------------------------

# 7. Forms

-   Associate labels with inputs
-   Clear validation messages
-   Identify required fields
-   Announce errors accessibly

------------------------------------------------------------------------

# 8. Responsive Design

-   Support mobile, tablet, and desktop
-   Zoom up to 200% without loss of functionality
-   Avoid fixed-width layouts

------------------------------------------------------------------------

# 9. Multimedia

-   Captions for instructional videos
-   Transcripts where appropriate
-   Avoid autoplay with sound

------------------------------------------------------------------------

# 10. Testing

Perform:

-   Keyboard testing
-   Screen reader testing
-   Automated accessibility scans
-   Manual WCAG review
-   Cross-browser verification

Recommended tools:

-   Lighthouse
-   axe DevTools
-   WAVE

------------------------------------------------------------------------

# 11. Accessibility Checklist

-   Images have alt text
-   Forms are labelled
-   Focus order is logical
-   Contrast requirements met
-   Errors are understandable
-   Navigation is consistent

------------------------------------------------------------------------

# 12. Continuous Improvement

Review accessibility:

-   Before major releases
-   After UI redesigns
-   Following user feedback
-   During periodic audits

------------------------------------------------------------------------

# 13. Acceptance Criteria

Accessibility is complete when core user journeys are operable with a
keyboard, compatible with assistive technologies, satisfy accessibility
testing, and align with WCAG 2.1 AA principles.
